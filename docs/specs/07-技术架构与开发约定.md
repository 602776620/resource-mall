# 07 · 技术架构与开发约定

## 1. 仓库结构

```

│  ├─ core/

│  │  ├─ security.py         # argon2 哈希、JWT 签发/校验、HMAC 签名短链
│  │  └─ deps.py             # get_db / get_redis / get_current_user / require_admin
│  ├─ db/
│  │  ├─ base.py             # Base、sessionmaker、engine
│  │  ├─ models/             # 03 号每张表一个文件
│  │  └─ init_db.py
│  ├─ schemas/               # pydantic 请求/响应模型
│  ├─ api/
│  │  ├─ v1/                 # 按域拆路由：auth.py products.py orders.py downloads.py admin/
│  │  └─ deps_reuse
│  ├─ services/              # 业务逻辑（算价、核销、券、限流、上传）
│  ├─ tasks.py               # 定时任务（超时取消/清理/自检）
│  └─ seed_admin.py
├─ alembic/
│  ├─ env.py
│  └─ versions/              # 每次 schema 变更一个迁移文件
├─ web/                      # 前端（Vite + React + TS）
│  ├─ src/
│  │  ├─ api/                # axios 实例 + 401 刷新拦截器 + 各域请求函数
│  │  ├─ router/             # react-router，前台/admin 两区 + 守卫
│  │  ├─ stores/             # 轻量状态（auth 用 localStorage token + 内存 user）
│  │  ├─ pages/              # 按 02 路由表一目录一页
│  │  ├─ components/
│  │  └─ lib/                # 金额分↔元、时间格式化、白名单渲染
│  └─ vite.config.ts         # proxy → 127.0.0.1:8000
├─ docker-compose.yml        # postgres:16 + redis:7
├─ requirements.txt          # 锁版本
├─ package.json              # 在 web/ 下
├─ .env.example              # 配置模板（.env 不入库）
├─ .gitignore
├─ backup.sh                 # 06 §6 备份
└─ docs/specs/               # 本规范集
```

## 3. 代码风格红线（后端）

1. **禁止字符串拼 SQL**，一律 ORM/参数化。
2. **禁止**在路由函数里写大段业务逻辑——路由只做「解析入参→调 service→出参」，业务进 `services/`。
3. 状态流转**必须**条件 UPDATE + rowcount（03 铁律），禁止读改写。
4. 金额只存分（int），禁止 float 参与计算。
5. 异常统一抛业务异常 → 全局 handler 转 04 错误体；**禁止**裸 500 透出堆栈。
6. 时区一律 UTC（`datetime.now(timezone.utc)`）；展示层转本地。
7. 每 service 函数可单测（依赖注入 db/redis session）。
8. 类型注解全覆盖，`mypy` 列入 10 号（MVP 不强卡）。

## 4. 代码风格红线（前端）

1. TS 严格模式（`strict: true`）；**禁止** `any`（确需 → `unknown` + 收窄）。
2. 金额分↔元转换只走 `lib/money.ts`，禁止页面内散落。
3. 路由守卫：`/admin` 未登录跳登录，非管理员 403 页（02）。
4. 所有请求经 `api/client.ts`（带 401 刷新重试一次）。
5. 富文本渲染必过 DOMPurify（02 §4.5 / 06 §5）。

## 5. Git 与 commit 规范

1. **独立仓库**：`resource-mall` 内 `git init`（共享库 programs 不提交，00 §3）。
2. 分支：`main`（可运行）+ `feat/Txx-简述`（当前任务）；MVP 单开发，PR 可选。
3. commit message：`<type>(<scope>): <简述>`，type ∈ feat/fix/refactor/test/docs/chore；scope 用任务号（T01…T10）。
4. **1 任务 ≈ 1 commit ≈ 一个可验收切片**；每个 commit 末尾追加：

```
Co-Authored-By: Claude Code <noreply@anthropic.com>
```

5. 提交前必过：`pytest` 绿 + 前端 `npm run build`（tsc）绿。

## 6. API 版本

- 统一 `/api/v1`；破坏性变更升 `/api/v2` 并保留 v1（MVP 只做 v1）。
- 响应/字段增删不破坏向后兼容（只增不改语义）。
