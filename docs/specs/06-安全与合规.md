# 06 · 安全与合规

## 1. 鉴权与越权矩阵

| 资源 | 游客 | 普通用户 | 管理员 |
|---|---|---|---|
| 商品列表/详情/预览 | ✅ | ✅ | ✅ |
| 我的订单/下载 | — | ✅ 仅本人（他人 order_no → 404） | ✅ 本人 |
| 下单/取消/我已付款 | — | ✅ 仅本人 | ✅ 本人 |
| /admin/* API | 401 | **403** | ✅ |
| 券码预检 | ✅（仅 valid 布尔，不暴露明细） | ✅ | ✅ |

红线：
1. 所有 `/admin/*` 路由统一 `Depends(require_admin)`（401/403 分层，不合并）。
2. 订单接口一律**按登录用户过滤**（`WHERE user_id = current_user.id`），禁止"传 user_id 查任意订单"参数。
3. 未上架/已删除商品对外接口**一律 404**（防存在性探测）。
4. 管理员 seed 走 CLI 命令 + 环境变量密码，**无注册自提权路径**。

## 2. 文件访问控制（最高优先级）

1. `downloads/`（已购资源）**禁止**静态挂载、禁止任何直接路径路由。唯一入口 = `/files/{token}` 签名短链。
2. 签名短链校验链（04 §5）：HMAC 验签 → 过期 410 → **消费前复核订单 pay_status='paid'**（撤销后立即失效）→ 流式输出。
3. `uploads/`（封面/预览/收款码图）允许公开，但经 `/media/{token}` 10min 短链（可公开但防枚举，且与 downloads 路径物理隔离）。
4. 上传文件名服务端重命名 `uuid+扩展名`（05 §8），原文件名仅展示字段；**路径穿越防护**：存储相对路径统一 `os.path.normpath` 后校验仍在目标目录内。
5. 验收（09）：直接 `GET /downloads/<真实文件名>` → **404**；猜遍历目录 → 404（无目录列表路由）。

## 3. 密钥与配置管理

| 项 | 存放 | 红线 |
|---|---|---|
| DB 口令 / Redis 密码 | `.env`（不入库）；docker compose 内引用 | 不进 git、不进镜像、不进日志 |
| `SECRET_FILE`（HMAC 签名密钥） | `.env`，`python -c 'import secrets;print(secrets.token_hex(32))'` 生成 | 丢失=所有在途短链失效（可接受）；泄露=可伪造下载链接，**必须轮换** |
| JWT secret | `.env` 同上 | 与 SECRET_FILE **分离** |
| 管理员初始密码 | 运行时 stdin 传入（seed 命令） | 不落盘任何文件 |

- `.gitignore` 必含：`.env`、`downloads/`、`uploads/`、`venv/`、`node_modules/`、`*.pyc`、`alembic` 备份。
- 日志**禁止**打印 token/密码/支付说明以外的敏感字段；支付说明（paid_note）属业务数据可入审计日志。

## 4. 密码与认证安全

- argon2id 哈希（参数 `m=64MB, t=3, p=4`）。
- access token 15min / refresh 7d，refresh **轮换**（旧 token 立即 revoke，防重放）。
- 登录失败不区分"用户不存在/密码错"（统一 401 BAD_CREDENTIALS），防账号枚举。
- 改密后：该用户**所有** refresh_tokens 置 revoked（踢下线）。
- JWT payload 只放 `sub(user_id), exp, jti`；不放 is_admin（每次从 DB 读，防权限缓存）。

## 5. 注入与 XSS

1. SQL 全走 SQLAlchemy ORM/参数化，**禁止**字符串拼 SQL（07 红线）。
2. 商品 description 入库前**白名单过滤**（02 §4.5），渲染端 React 用 `dangerouslySetInnerHTML` 前再过 DOMPurify。
3. 搜索 keyword 只进 LIKE 参数，不拼 SQL。
4. CORS：dev 仅放行 `http://127.0.0.1:5173`；不配 `allow_origins=["*"]`（07 环境配置）。
5. 文件下载 `Content-Disposition: attachment`，防浏览器直接渲染 zip 内 HTML（zip 本身不会渲染，但 pdf/图片类资源文件强制 attachment）。

## 6. 备份与恢复

| 对象 | 策略 | 工具 |
|---|---|---|
| PostgreSQL | 每日 02:00 全量 `pg_dump -Fc` 到 `backups/pg/`（保留 14 份） | 08 号提供 `backup.sh` |
| Redis | 默认 RDB 快照（`save 900 1`）在容器卷内；**限流数据可丢**（丢失=配额清零，可接受） | — |
| downloads/uploads | 本地磁盘，**MVP 不自动备份**（列入 10 号 OSS 迁移后解决） | — |

恢复验收（09）：从最近 pg_dump 恢复到新库，E2E 核心路径仍可通过。

## 7. 审计日志要求

1. 必录动作（03 audit_logs.action 枚举）全覆盖；核销/撤销/删除商品/停用券/禁用用户**强制**留痕。
2. 记录：操作人(admin_id)、动作、对象(type+id)、理由、IP、时间（UTC）。
3. audit_logs **只增不改不删**（无 UPDATE/DELETE 接口）；保留期 MVP 不限。
4. 撤销（revoke）理由必填 ≥5 字，防"误点"无据可查。
