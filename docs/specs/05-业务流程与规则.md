# 05 · 业务流程与规则

## 1. 购买-支付-核销-下载 全链路

```
用户 ──选商品──▶ POST /orders（服务端算价+试扣券）
                     │ 201 {order_no, amount_cents, expire_at}
                     ▼
              待支付页（收款码 + 金额 + 订单号 + 30min 倒计时）
                     │  线下扫码付款（个人收款码，无自动回调）
                     ▼
              点「我已付款」POST /paid-submitted {note}
                     │ paid_submitted_at 置位，进入核销队列
                     ▼
管理员核销工作台：按 order_no 精确检索
  三方比对 SOP（§2）：① 金额一致 ② 渠道一致 ③ 支付说明可佐证（交易时间/尾号）
                     │ 核销 POST /confirm {pay_channel, note}
                     │ 条件更新 pending→paid（rowcount 判定，03 铁律 1）
                     ▼
用户侧：待支付页 5s 轮询 → 状态变 paid → 引导去下载中心
                     │
                     ▼
下载中心「下载」GET /orders/{no}/download
  校验 paid → Redis 限流(§4) → 消费前复核 paid → 302 /files/{token}(15min)
                     │ 过期/超限/撤销 → 410/429/403
                     ▼
StreamingResponse 断点续传
```

**超时取消**：后台任务每 60s 扫描 `pay_status='pending' AND expire_at < now()` → 批量置 cancelled（条件更新）。券不自动退回——**被超时取消订单占用的券用量需回滚**（见 §3 券规则）。

## 2. 核销 SOP（人工操作强制规范，写入核销工作台页面顶部提示）

1. 在核销工作台队列中找到该用户**提交的订单**（队列 = paid_submitted 非空，按提交时间正序）。
2. **三方比对**（缺一不可，禁止模糊核销）：
   - 收款方收款记录中的**金额** == 订单 `amount_cents`
   - 收款记录**渠道** == 用户选择的 pay_channel（微信/支付宝）
   - 用户 `paid_note`（支付说明，如"17:20 支付宝 尾号 1234 支付"）与收款记录可相互佐证
3. 金额不一致 → **不得核销**，在订单详情标记/联系用户。
4. 核销时选择渠道并填写 note（选填，记录比对依据）；界面要求输入**订单号后 6 位**二次确认。
5. 核销/撤销全部写入 audit_logs（操作人+IP+理由），可追溯。
6. 发现**重复核销**（409 CONFLICT）→ 说明并发或误操作，检查 audit_logs 确认首次核销记录，不重复操作。
7. 错核销处理：已核销订单走**撤销**（paid→revoked，理由必填）+ 线下重新收款流程，不做"回退到 pending 再核销"。

## 3. 优惠券规则

| 规则 | 说明 |
|---|---|
| 类型 | `fixed`（固定减，单位分）/ `percent`（按比例，1~95 整数百分比） |
| 抵扣额 | percent：`floor(original_cents * value / 100)`；fixed：`min(value, original_cents)` |
| 0 元单 | 允许（抵扣后 amount=0）：待支付页显示「已全额抵扣，请提交订单」，跳过扫码直接「我已付款」（说明填"0元单"）；管理员核销时金额比对为 0 即通过 |
| 核销时机 | **下单时**原子试扣（03 铁律 2 同事务），不是支付成功后扣 |
| 防重放 | 同一券码同一订单重复提交 → 试扣 UPDATE rowcount=0 → 409；一券一单（coupon_usages.order_id UNIQUE） |
| 超时取消回滚 | 订单 cancelled 时：`UPDATE coupons SET used_count=used_count-1 WHERE code=...` + 删 coupon_usages 行（同事务）；**已 paid 订单取消（撤销）不回滚券**（券已消耗，与撤销语义一致） |
| 并发验收 | 同一券 max_uses=N，并发 10 个不同用户同时下单 → 恰好 N 单成功（09 号用例） |
| 有效期 | `valid_from ≤ now ≤ valid_to`（UTC）；停用（is_active=false）后不可新用，已用订单不受影响 |

## 4. 下载限流规则

- **配额**：同一订单 **7 个自然日内最多 50 次**（以订单 created_at 为窗口起点）。
- **实现（Redis）**：key = `dl:quota:{order_id}`，首次签发 `SET key 1 EX 604800`；每次成功签发下载链接前 `INCR`，超 50 → 429 DOWNLOAD_QUOTA_EXCEEDED。
- 每次签发**同时**写 download_logs（审计留痕，Redis 丢数据时可重建配额近似值）。
- **降级**：Redis 不可用 → 查 download_logs 近 7 天 COUNT 兜底；DB 也不可用则 503（不放行——文件交付宁缺毋滥）。
- 签名短链 15 分钟内可重复直接访问 `/files/{token}` **不计配额**（防大文件重试误伤），配额只在 `/orders/{no}/download` 签发时计数。

## 5. 接口限流规则（Redis 滑窗）

| 接口 | 维度 | 阈值 | 降级（Redis 挂） |
|---|---|---|---|
| /auth/login | IP | 5 次/min | **放行**（DB 兜底：查登录失败日志近 1min 计数）；DB 也挂 → 放行+告警 |
| /orders（创建） | IP | 10 次/min | 同上 |
| /orders/{no}/download | 用户 | 20 次/min | 查 download_logs 近 1min COUNT |
| 其余写接口 | IP | 60 次/min | 放行+告警 |

降级原则：**限流可降级，鉴权/支付状态不可降级**（03 铁律不走捷径）。

## 6. 缓存规则（Redis）

| 缓存项 | key | TTL | 失效时机 |
|---|---|---|---|
| 商品列表首页块 | `cache:home` | 120s | 商品增删改/上下架主动 DEL |
| 分类+字典 | 进程内存 | — | 重启加载 |

缓存降级：Redis 挂 → 直查 DB（功能不受损）。

## 7. 后台定时任务（FastAPI lifespan 启动，asyncio task）

| 任务 | 频率 | 动作 |
|---|---|---|
| 订单超时取消 | 60s | pending 且 expire_at<now → cancelled（含券回滚 §3） |
| refresh_tokens 清理 | 每日 03:00 | 删过期行 |
| 健康自检 | 30s | 探测 DB/Redis，失败打 error 日志（/health 实时反映） |

任务必须**幂等**（重复执行无副作用），单实例运行（MVP 单进程，07 号约定）。

## 8. 上传文件规则

| 类型 | 目录 | 单文件上限 | 数量上限 | 类型白名单 |
|---|---|---|---|---|
| 封面 | uploads/covers/ | 5MB | 1 | jpg/png/webp |
| 预览图 | uploads/preview/ | 5MB | 9 | jpg/png/webp/gif |
| 预览样本 | uploads/preview/ | 20MB | 3 | pdf/zip/mp4/png/jpg |
| 资源文件 | downloads/ | 2GB | 1 | zip/rar/7z/pdf/mp4/png/jpg/txt（扩展名+MIME 双校验） |

- 服务端二次校验（不信任前端）；文件名**重命名**为 `uuid.hex + 原扩展名`（防覆盖/路径注入），原名只存 file_name 字段。
- 同目录同 uuid 冲突 → 重新生成（概率可忽略，仍校验）。
