# 03 · 数据模型（PostgreSQL 16）

## 0. 约定

- 金额一律 **BIGINT 分**（禁止 float/decimal 存金额，API 与展示层分↔元转换）。
- 时间一律 `TIMESTAMPTZ`，库内统一 UTC（`now()`）。
- 多值字段：`tags` 用 `TEXT[]` 原生数组；`preview_media` 用 JSONB（结构 `{kind, url, name?}`）。
- 软删除：MVP 不做（商品禁删规则见 02），直接物理删除但**有订单的商品禁删**。
- 主键：`BIGSERIAL`（MVP 足够；预留换 UUID 的代价见 10 号）。
- 迁移：Alembic，**每次 schema 变更 = 独立迁移文件 = 独立任务/commit**。

## 2. 状态机与实现铁律

### orders.pay_status 状态机

```
        ┌────────── 用户取消 / 30min 超时任务 ──────────┐
        ▼                                               │
pending ─────────────────────┐                          │
  │                          └──────────▶ cancelled     │
  │ 管理员核销(条件更新)                                 │
  ▼                                                       (不可逆)
paid ── 管理员撤销(条件更新, 理由必填) ──▶ revoked (终态)
```

| 转移 | 触发者 | SQL 模式 |
|---|---|---|
| pending→paid | 管理员核销 | `UPDATE orders SET pay_status='paid', paid_at=now(), pay_channel=$1 WHERE id=$2 AND pay_status='pending'`，**rowcount=0 即 409**（已被并发核销/取消） |
| pending→cancelled | 用户 / 超时任务 | 同上 `pay_status='pending'` 条件；超时任务批量：`WHERE pay_status='pending' AND expire_at<now()` |
| paid→revoked | 管理员撤销 | `WHERE id=$1 AND pay_status='paid'`，rowcount=0 即 409 |

**铁律 1**：一切状态流转必须走条件 UPDATE + rowcount 判定，禁止「先 SELECT 再 UPDATE」的读改写。**铁律 2**：券码核销与订单创建同事务——

```sql
-- 同事务内，先试扣券，失败整体回滚
UPDATE coupons SET used_count = used_count + 1
WHERE code = $1 AND is_active
  AND used_count < max_uses
  AND now() BETWEEN valid_from AND valid_to;
-- rowcount = 0 → raise → 订单回滚（订单未 INSERT 成功）
INSERT INTO coupon_usages(code, order_id, discount_cents, used_at) VALUES ($1, $2, $3, now());
```

**铁律 3**：订单创建全程**服务端算价**（商品价×1 − 券抵扣），客户端传金额一律忽略。percent 券抵扣额 = `floor(original_cents * value / 100)`。
