# 09 · 测试与验收标准

> 勾选约定：每项 `[x]` 才算完成；测试代码在 `app/tests/`（pytest）与 `web/src/**/*.test.tsx`（vitest，MVP 仅关键组件）。
> 每个任务 commit 前：本任务对应验收项必须勾选且测试绿。

## 1. E2E 关键路径（人工 + 接口脚本混合，最终验收必过）

- [ ] **P0 环境**：`docker compose up -d` → 双容器 Up → `alembic upgrade head` → 应用启动 → `GET /health` = db/redis 双 ok
- [ ] **P1 买家闭环**：注册 → 登录 → 浏览列表（分类/价格/关键词筛选各验一次）→ 详情看预览 → 输入券码下单 → 待支付页（收款码+订单号+金额正确）→ 点「我已付款」填说明 → 管理员核销 → 轮询见 paid → 下载中心下载成功（文件完整）
- [ ] **P2 管理员闭环**：seed 管理员 → 登录进 /admin → 上传商品（封面+预览图2+样本1+资源文件）→ 上架 → 生成券码 → 核销一笔 → 撤销一笔（理由）→ 查看审计日志（核销/撤销均留痕）
- [ ] **P3 安全负面**：
  - [ ] 未登录访问 /admin API → 401；普通用户访问 → 403
  - [ ] 直接 `GET /downloads/<真实资源文件名>` → 404（目录遍历若干次仍 404）
  - [ ] 签名短链改 1 字符 → 403 TOKEN_INVALID；等 15min 后访问 → 410 TOKEN_EXPIRED
  - [ ] 撤销后：旧签名短链再访问 → 403 ORDER_NOT_PAID
  - [ ] 用户 A 用用户 B 的 order_no 查/下/下载 → 404
  - [ ] 未上架商品 GET /products/{id} → 404
  - [ ] 登录连续失败 5 次后第 6 次 → 429
- [ ] **P4 并发**（pytest，见 §3）：
  - [ ] 同券 max_uses=3，10 并发不同用户下单 → 恰 3 成功 7 个 409
  - [ ] 同订单两人（管理员双开）并发核销 → 恰 1 成功 1 个 409
  - [ ] 同订单 60 并发下载签发 → 50 成功、10 个 429（quota 内）/或窗口正确
- [ ] **P5 超时**：造 expire_at 已过期的 pending 订单 → 等任务一轮（或手动触发）→ cancelled + 券用量回滚
- [ ] **P6 门禁**：`pytest` 全绿 + `cd web && npm run build`（tsc strict）全绿
